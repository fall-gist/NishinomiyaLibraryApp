# 西宮市立図書館 家族用アプリ 仕様書

最終更新: 2026-07-22(予約バックエンド・UIを実装)

## 1. コンセプト

西宮市立図書館を使う**家族のための非公開Androidアプリ**。
家族全員分の「借りている本・返却期限・予約の状況・マイ本棚」を1つのアプリに集約し、
返し忘れ・受取忘れをなくす。

- **アプリの表示名(ランチャー名)は「西宮市立図書館」**(`app_name`)
- ストア公開はしない(家族の端末に直接インストール)
- 図書館公式サイト(LICS-XP)への書き込みは必要最小限に限る。2026-07-26時点で実装済みの
  書き込みは、ユーザーが最終確認した**予約確定**だけであり、本仕様§3.10の安全策のもとで送信する
- **2026-07-26改定**: 「自動予約や予約以外の書き込みは行わない」という制限を、リポジトリ所有者の
  判断で撤回した。撤回は「実装する」ことを意味しない。書き込み操作を追加する場合は、機能ごとに
  設計を起こし所有者の承認を得て、本仕様へ追記してから実装する。検討中のものは
  `docs/handoff.md` の「今後の構想」を参照

## 2. アカウント

- 家族**5人分**の利用者アカウントを登録できる(人数は拡張可能な設計とする)
- 各アカウント: 表示名 / 識別色 / 図書館カード番号 / パスワード
- 認証情報は**端末内に暗号化保存**(Android Keystore)。外部送信・リポジトリ格納は厳禁

## 3. 機能仕様

### 3.1 ホーム(家族統合ビュー)

- 家族**全員分を統合**したダッシュボード。メンバーは名前+識別色で区別
- 表示内容:
  - 返却期限が近い本(期限順、期限超過は強調)
  - 受取可能になった予約
  - 最終同期時刻
- メンバーによる絞り込みフィルタ

### 3.2 蔵書検索

- キーワード検索(かんたん検索相当)。オートコンプリート候補表示(公式JSON API)
- 検索結果: タイトル / 著者 / 出版社 / 貸出可否○×(公式JSON API `getIsLend`)
- 書誌詳細: 書誌事項+所蔵一覧(館 / 請求記号 / 配架場所 / 在庫状態)
- 検索結果・書誌詳細など、タイトルコード(`tilcod`)を持つ画面では、対象メンバーを
  指定して「即時予約」または「カートへ追加」を選べる(§3.10)。画面によっては両方を
  併置してよい

### 3.3 利用状況(メンバー別詳細)

- 貸出中一覧: 資料名 / 貸出館 / 貸出日 / 返却期限日
- 予約中一覧: 資料名 / 受取館 / 予約順位 / 予約状態 / 取置期限

### 3.4 マイ本棚(参照)

- 公式サイトの「マイ本棚」を読み取り専用で表示(資料名 / メモ / 登録日)
- 書誌詳細への導線あり

### 3.5 開館カレンダー

- **一度に一館のみ表示**(ごちゃつき防止)。表示館はドロップダウン等で選択
- 対象: 全12施設(中央 / 北口 / 鳴尾 / 北部 / 越木岩 / 若竹 / 段上 / 上ケ原 / 甲東園 / 高須 / 山口 / 義務教育校)
- 設定の「既定館」を初期表示する。既定館はカレンダー専用ではなく、予約受取館の
  初期値にも使うアプリ共通設定である(既存の保存キーとの互換性は維持する)
- 休館日をカレンダー形式で表示(公式サイトから約3ヶ月分取得)

### 3.5b 読書記録(2026-07-19追加・優先実装)

「この本、読んだことがあるか」を予約・貸出候補選びの場で即座に確認するための機能。
本アプリの中心動機のひとつ。

- データ源: 公式サイトの**読書履歴**(`gamen=usrread`)。メンバーごとに全件を取り込み、
  ローカルDBに**永続蓄積**する(他のデータと違い、同期での全削除・再取込はしない)
- 初回同期でメンバーごとに全履歴を取得(100件/ページでページング)。以降の同期は
  先頭ページから既知レコードに当たるまでの**差分取込**
- 保険として、毎回の同期時に**現在の貸出中資料も読書記録へ併合**する
  (サイト側の履歴機能が無効なメンバーでも、アプリ利用開始以降の記録は貯まる)
- 重複判定キー: メンバー+タイトルコード+貸出日
- 機能:
  - **一覧**: 貸出日の新しい順。メンバーフィルタ対応
  - **テキスト検索(必須)**: 書名・著者の部分一致。全角/半角・大文字小文字の
    ゆらぎを吸収した正規化列で検索する
  - **既読バッジ**: 蔵書検索の結果・書誌詳細に「よんだ(だれが・いつ)」を表示する
    (タイトルコード一致で判定)
- 注意: サイトの読書履歴は**アカウントごとに有効化が必要な場合がある**。
  メンバーの履歴が0件のときはその旨を表示する

### 3.6 通知

| 通知 | タイミング | 形式 |
|---|---|---|
| 返却期限リマインダー | 期限の**n日前**(既定: 前日=1日前。**日数は設定で変更可**、2026-07-20追加) | 家族**まとめて1通**(例:「明日返却: パパ3冊・長女2冊」) |
| 予約受取可能 | 同期時に受取可を検知したら | まとめて1通 |

- 順位上昇などその他の通知は**行わない**
- **通知のオン/オフ設定は必須**(種類ごとに切替可能)

### 3.7 同期

- 自動同期: **毎日18時に1回**(閉館後を想定)。**時刻は設定で変更可能**
- 手動同期: プルリフレッシュ
- 取得結果はローカルDB(Room)にキャッシュし、オフラインでも最終取得状態を表示

### 3.8 表紙画像

- openBD等の公開APIからISBNで**都度取得**
- **メモリキャッシュのみ**(アプリ終了で消える)。**ディスクキャッシュは持たない**
  (ストレージ消費を避けるため)
- 非同期・遅延ロードで、画像待ちがUI操作をブロックしないこと

### 3.9 新着資料(2026-07-20追加)

- データ源: 公式サイトの**新着資料**ページ(認証不要の公開ページ)。ジャンル一覧
  (`WOpacMsgNewMenuDispAction.do`)→各ジャンル(`WOpacMsgNewMenuToMsgNewListAction.do?newMenuCode=NN`)
- 公式サイトはジャンル別だが、本アプリは**ジャンルを保持せず全ジャンルを統合した書誌リスト**として扱う
  (tilcodで名寄せ・重複排除)
- 取得項目: 書名 / 巻次 / 著者 / 出版者 / 出版年月 / 分類 / 貸出可否(○×)/ tilcod
- ローカルDB(Room)に**全置換**でキャッシュ。画面を開いたセッションで1回取得し直し、手動「更新」も可能
- 画面内で書名・著者の**絞り込み**ができる(読書記録と同じ正規化)
- サイト負荷配慮: 全ジャンルを巡回するため**リクエスト間500ms以上**(既存レート制御を流用)、
  自動同期には載せず**画面表示時/明示更新時のみ**取得する

### 3.10 予約(2026-07-22確定・バックエンド実装済み)

予約機能は、ユーザーが明示操作し最終確認した予約確定だけをサイトへ送る。
直接予約通信、ローカルカート、予約カート画面・書誌詳細からの導線・最終確認画面は実装済みである。
`ReservationUiController`が受取館、最終確認、処理結果を共有する。カート追加はローカルRoom更新だけで、
図書館サイトへの予約送信は最終確認の肯定操作だけで行う。

#### 予約候補とローカルカート

- 公式サイトのカートは一切使わない。アプリ独自の**ローカルカート(Room)**だけを使い、
  カートへの追加・削除時にはサイト通信を行わない
- カートへ追加するときに、対象メンバーを必ず選択してカート項目に固定する。後から
  メンバーを暗黙に入れ替えない
- 受取館はカート追加時には固定せず、予約確定時にバッチ全体で1館を選ぶ。設定の
  「既定館」を初期選択する。メンバー別既定館は設けない
- 連絡方法は**Email固定**であり、選択UIは置かない
- 検索結果・書誌詳細などから「即時予約」も選べる。即時予約は、カートへ永続追加せず、
  共通の予約バッチ処理へ1件の一時項目として渡す

#### 確定処理と結果

- 確定前に、対象資料・対象メンバー・受取館を示す最終確認を必ず表示する。確定後は、
  項目をメンバーごとにグループ化し、各メンバーについてログイン済みの分離セッションを
  1回だけ確立して、資料を順次直接予約する。既存のリクエスト間500ms以上の制御を維持する
- POST後に成否不明となった項目ごとに予約一覧を即時1回取得し、`tilcod`を確認できた場合だけ次資料へ進む。
  即時照合済み項目は末尾再照合しない。`Submitted`/既知重複など未照合項目が残る場合だけ、処理終了時に
  予約一覧を最大1回取得して解決する。成功判定を画面alertの文言に依存させない
- 成功応答HTMLの対象資料を特定できる構造は未検証のため、確定POST後に成否不明となった項目は
  **その場で予約一覧を読み取り照合**する。対象`tilcod`を確認できた場合だけ同一セッションで次の
  資料へ進み、確認不能なら再送せず当該メンバーを停止する。この安全策により資料ごとの追加読取通信が発生する
- `Success` と `AlreadyReserved` は目的状態が達成済みなのでローカルカートから削除する。
  `Failure` と `Unknown` は残し、画面にメンバー別・資料別の部分成功結果を表示する
- 認証失敗はそのメンバーの残件だけを中止し、他メンバーは続行する。予期しないレスポンス、
  パース失敗、サイト変更の疑いでは、そのメンバーの残件を中止する
- 設定の既定館または利用者が選択した受取館が、その予約確認画面のサイト選択肢にない場合は
  エラーにする。別の館へ暗黙にフォールバックしない

#### 再試行と書き込みの境界

- セッション切れが**確定POST前**に明確に検出できた場合だけ、新しいセッションで1回だけ
  再試行できる。確認画面の表示から確定までUI待機を挟まず、ログイン→確認GET→確定POSTを
  同一セッション内で連続実行する
- 確定POST後の通信断など、成否が不明な場合は再送しない。予約一覧の`tilcod`照合で
  `Success` / `AlreadyReserved` / `Unknown` を解決する。重複予約は`AlreadyReserved`として
  解決済み扱いにする
- 本節が定めるのは予約確定の安全策である。予約確定以外の書き込みを行わないという制限は
  2026-07-26に撤回された(§1)。新しい書き込み操作を追加する場合も、読み取り通信から分離した
  専用ゲートウェイへの隔離、副作用のある送信は一回限り、成否不明時は再送せず照合で解決、という
  本節の不変条件を同様に満たすこと

#### 設計判断

- **不採用: 公式サイトカートを正とする案。** 追加ごとに通信が必要で、アカウント切替時の
  ログイン、サイト側の残骸、部分失敗の管理が増える
- **採用: ローカルカート+直接予約。** 通信を減らし、複数アカウントを分離して扱える。一方で、
  アプリ側にカート永続化、部分成功の表示、予約一覧による照合を実装する必要がある

## 4. 非機能要件

- **サイト負荷への配慮**: 自動同期は1日1回。リクエスト間の最小間隔500ms(`LicsXpSession`)は維持する。
  > 2026-07-28改定: 手動更新の5分クールダウンは所有者の判断で撤回した。家庭内のみでの使用を
  > 想定しており、サーバに負荷となるほどのリクエストを送ることはそもそもできないため、利用者の
  > 良心に委ねる。5分間隔では実機検証にも支障があった。リクエスト間の最小間隔500msは今回の対象外で、
  > 引き続き維持する。
- **パーサの分離**: スクレイピング部分は独立モジュールとし、サイト改修時に
  差し替えやすくする。パース失敗はアプリ内で検知・表示する
- **予約の安全性**: 予約確定は明示操作と最終確認を通った場合だけ送信する。成功は予約一覧の
  `tilcod`照合で検証し、POST後に成否不明なら再送しない
- **拡張性**: 予約直接実行は既存の読み取り通信から分離した境界に置く。予約確定以外の書き込みを
  追加する場合も同じ境界の内側に置き、機能ごとに本仕様へ追記してから実装する
- 対応OS: Android 8.0 (API 26) 以上
