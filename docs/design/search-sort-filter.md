### 2.1 詳細検索の送信

- 入力画面: `GET WOpacTifSchCmpdDispAction.do`（`tif_search_form.html`）
- 実行: `POST WOpacTifSchCmpdExecAction.do?tifschcmpd=1`。本文（実測で通ったもの）:
  `chu_search_ini=1, hash=, jin=0, returnid=, gamenid=tiles.WTifSchCmpd, chkflg, loccodschkflg=nocheck,
  langcodschkflg=nocheck, targetsChkflg=nocheck, targetsAvChkflg=nocheck, tifKanrabtn=, tilkbncodschkflg=nocheck,
  condition{1,2,4,5}, condition{1,2,4,5}Text, range{1,2,4,5}=0, mixing{1,2,4,5}=0, condition3=5, condition3Text, range3=0,
  dispmaxnum=20, disporder=0, yearselect=0, yearstart, monthstart, yearend, monthend`
- 語の欄は4つ（`condition1`・`2`・`4`・`5`）。項目コード: 書名=`0`、著者名=`1`、出版者=`2`、全項目=`7`（ほかに件名=`3` 等）。
  `range`=`0` は「含む」、`mixing`=`0` は AND
- 分類は `condition3=5`・`condition3Text`
- 資料の種類は `mngshus`（チェックボックス、複数可）: `1` 一般、`2` 児童、`3` 雑誌・新聞、`4` ＣＤ、`5` ビデオ・ＤＶＤ、
  `6` デイジー、`7` その他視聴覚、`8` 大型絵本。1つ以上選んだら `chkflg=check`、無ければ `nocheck`（サイトの `kensaku()`）
- 出版年月: `yearselect=0`（出版年月）、`yearstart`（4桁）・`monthstart`（2桁まで）・`yearend`・`monthend`
- **送信は UTF-8**（Windows の curl で引数をそのまま送ると文字化けして別の結果になった。アプリの OkHttp の FormBody は UTF-8）
- 件数: 本文の「該当件数は N 件です」。1ページ20件

## 3. 設計

### 3.1 検索条件（ドメイン）

`SearchQuery`（名前は任せる）:
- キーワード（全項目）、書名、著者、出版者、分類（いずれも文字列。空は未指定）
- 出版年月の範囲（から: 年・月、まで: 年・月。いずれも省略可）
- 資料の種類（上の8種の集合。空は未指定）
- 在庫状況（全て／貸出可のみ／館内閲覧のみ。既定は全て）
- 並べ替え（項目6種のいずれか＋昇順／降順。未指定ならサイトの既定の並び）

検証: 語・分類・年月・種類のどれか1つは必要。年は4桁、月は1〜12。「から」が「まで」より後なら誤り。

キーワード検索は「キーワードだけを持つ SearchQuery」として同じ経路で送る。

### 3.2 通信（`LicsXpClient`、閲覧の列 `@BrowseSession`）

ページを取るたび、次の手順を1つの閲覧セッションの**排他区間**（`withExclusiveRequestSequence`）の中で順に行う（従来の「毎回検索し直してからページを開く」作りを踏襲）。
サーバ側の検索状態（並べ替え・在庫状況）が途中で別の閲覧の通信に変えられないための措置で、その間、他の閲覧操作（自動補完・書誌詳細など）は待たされる:

1. `GET WOpacTifSchCmpdDispAction.do`（セッション確立・トークン）
2. `POST WOpacTifSchCmpdExecAction.do?tifschcmpd=1`（§2.1。語の欄は キーワード→書名→著者→出版者 の順に、指定されたものだけを `condition1`・`2`・`4`・`5` へ詰める）。
   応答が0件の画面（§2.4。入力画面＋「該当する書誌がありません。」）なら、その時点で空の結果を返し、以降を送らない
3. 在庫状況が「全て」以外なら `WOpacWebTifTilListStockStateSearchAction.do`（この応答が0件の画面でも同様に打ち切る）
4. 並べ替えの指定があれば、**結果画面の `LBForm` の hidden `sortKey`・`isAsc`** で状態を判断する（見出しの `▲▼` は実行直後に「書名▲」と出るため当てにしない。§2.4）。
   hidden の `sortKey` が望む項目のキーと違えば必ず `notPageSort=1` で1回送り、送った後に `isAsc`（1=昇順、0=降順）が望む向きと違えばもう1回送る。
   **2回送っても望む状態にならなければ失敗とする**（サイトの仕様変更の検知）
5. 2ページ目以降は `startIndex` でページを開く
6. 最終応答で、並べ替えの指定があれば hidden の `sortKey`・`isAsc` と見出しの `▲▼` の**両方**が望む値であること、
   在庫状況の指定があれば `select[name=stockState]` の選択値が指定と同じであることを確かめ、違えば失敗とする
7. 次ページの有無は「次へ」リンクの有無、または `page * 20 < 件数` のどちらかが真なら「あり」（片方の表示が変わっても取りこぼさない。矛盾時は多く出す側）

失敗は `LibraryError.Parse("search_sort" / "search_stock", …)`。旧かんたん検索の通信は `LicsXpClient.searchByEsKeyword` に残してある（§7-1の戻し用。現在は未使用）。

閲覧のみの通信なので、書き込みの規則（1回だけ送る等）の対象外。ただし通信の回数が増える（並べ替え・在庫状況ありの2ページ目で5回程度）。開始間隔500msの規則はそのまま。

### 3.3 結果の解析

表の解析器を新たに作る（`tif_search_result*.html` で固定）。1件: 資料番号（`tilcod`）、書誌種別、書名、著者、出版者、出版年月、分類、貸出可否（`○`→可、`×`→不可、その他→不明）。
件数（「該当件数は N 件」）、次ページの有無、並べ替えの現在の項目と向き（`▲▼`）も取る。
既存の `SearchHit`・`SearchPage` は、画面・選択モード・一斉操作で使っているので、**必要な項目を足す形で広げる**（既存の項目の意味を変えない）。
貸出可否は表の列から取れるので、検索結果について1件ずつ `getIsLend.do` を呼ぶ処理は不要になる（呼び出し元の扱いは実装時に確認）。

### 3.4 画面

- 検索画面: 従来のキーワード欄（自動補完つき）はそのまま。横に「詳細検索」を置き、押すと詳細検索の入力欄（§3.1 の項目）を開く
- 結果:
  - 1件の表示に、書誌種別・出版者・出版年月・分類を足す（狭い画面で読めるよう、行を分けてよい）
  - 並べ替え: 結果の上に6項目のボタン（書誌種別・書名・著者・出版者・出版年月・分類）を並べる。1回押すと昇順、もう1回で降順、
    選んでいる項目に `▲`／`▼` を付ける。別の項目を押すとその項目の昇順。並べ替えると1ページ目から読み直す
  - 「絞り込み」: 詳細検索の入力欄を今の条件入りで開き、項目を足して検索し直す（キーワードも欄に残る）
  - 今の条件を結果の上に短く表示する（例: 「キーワード: ドラゴンボール／書誌種別: 児童／出版年月: 2010年〜」）
- 選択モード・一斉操作・書誌詳細・「検索結果のリセット」（`docs/design/search-result-reset.md`）の扱いは従来どおり
