## 1. 画面の構成

### 1.1 入口（2026-09-27 所有者確定）

**ハンバーガーメニュー（ドロワー）の1項目**として、「設定」の真下に「バージョン情報」を置く。

ドロワーの並びは `Destination` の宣言順に従う（`LibraryApp.kt:99`）。`SETTINGS` の直後に
`VERSION_INFO("バージョン情報", …, primary = false)` を足せば、設定の真下に並ぶ。
下部ナビには出さない（`primary = false`）。区切り線と「公式サイト」はその下のまま。

### 1.2 上部

アプリ名と `versionName`（`BuildConfig.VERSION_NAME`）だけを出す。
**ビルド番号・コミットの識別子は出さない**（2026-09-27 所有者確定）。

```
西宮市立図書館
Ver.1.10
```

アプリ名は `strings.xml` の `app_name`（「西宮市立図書館」）をそのまま使う（実装時に確認）。

### 1.3 下部: 更新履歴（2026-09-27 所有者確定の書き方）

- 新しい版を上に並べる。1つの版ごとに「版番号と日付」の行と、その下に本文
- **本文は箇条書きにせず、短文で端的に書く**（複数の文でもよい）
- **更新内容のすべては載せず、主要な項目だけ**を書く。まったく異なる項目が複数あれば並べて書く
- **文体は文語体**（である調・体言止め）。丁寧語は使わない
- 1.0 は個別の機能を並べず「リリース」とする
- 内部の用語（コントローラ名など）は使わない

### 1.4 文面の置き場所

更新履歴の文面はアプリのコードの中に持つ（純粋な Kotlin のデータとして1か所にまとめる）。
通信で取りに行かない。開発者向けの記録（`docs/design/release-build.md` の履歴表）とは別物として扱い、
版を上げるときに両方を更新する。

## 4. 実装（文面の確定後）

- `Destination` に `VERSION_INFO` を `SETTINGS` の直後へ追加する（ドロワーの並び、§1.1）
- 更新履歴の文面を Kotlin のデータとして1か所に置く。**履歴の先頭の版番号と `BuildConfig.VERSION_NAME` が
  一致することを単体テストで固定する**（版を上げたのに履歴を書き忘れる、を防ぐ）
- 画面は他の画面と同じく `ScreenTopBar`（タイトル「バージョン情報」、ハンバーガーボタン）を持つ通常の画面とする
