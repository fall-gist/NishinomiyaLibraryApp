# 長押しによる選択モード 設計書

作成日: 2026-09-20
状態: **設計中（§3.2 の判断を所有者へ確認中）**
モック: `docs/mockups/selection-mode.html`
位置づけ: 3段階の改修の第2段階（1. 検索・新着のリセット=完了、2. 本件、3. 読書記録の複数選択）

## 1. 目的

一覧にチェックボックスが常に出ている状態をやめ、**書誌タイルの長押しで選択モードに入る**方式へ変える。
選択モードの間は、タイルのタップが選択の切り替えになる。あわせて、チェックボックスの横に置いていた
状態表示（「延長可能」「順番待ち」等）を書誌名の下へ移す。

## 2. 所有者による確定事項（2026-09-20、モックへの回答）

1. 処理中を知らせる帯は画面の**下**に置く（第3の改修。本設計書の対象外だが、位置だけ確定）
2. **「すべて選択」は置かない**。誤タップで件数が一気に増えるのを避けるため
3. 「長押しで複数選択」の案内は**常に出す**。邪魔なら後で設定を検討する
4. **予約カート画面は現在のまま**（チェックボックスを常に表示）
5. 選択が0件になっても**選択モードから自動では抜けない**

## 3. 設計

### 3.1 対象の画面

| 画面 | 選択の持ち主 | 一斉操作 |
|---|---|---|
| 貸出中 | `LoanExtensionUiController.selectedKeys` | 一斉延長 |
| 予約中 | `ReservationCancelUiController` | 一斉取消 |
| 蔵書検索 | `SearchScreenController.selectedCartTilcods` | 予約・カートへ追加・本棚へ追加 |
| 新着資料 | `NewArrivalsScreenController.selectedCartTilcods` | 同上 |
| 読書記録 | （未実装。第3段階で追加） | 第3段階で決める |
| 予約カート | `ReservationUiController` | **対象外**（§2-4） |

選択モードのフラグ（`selectionMode: Boolean`）は、**選択集合と同じコントローラ**に置く。
画面ローカル（`remember`）に置くと、選択集合との整合（画面を離れたとき、処理が完了したとき）を
2箇所で管理することになり、過去に踏んだ lost update と同種の取りこぼしを招く。

### 3.2 長押しとテキスト選択の競合（**所有者の判断待ち**）

`LibraryApp.kt:282` は画面全体を `SelectionContainer` で包んでおり、**いまは一覧の文字を長押しすると
テキスト選択（コピー）が始まる**。行の長押しに選択モードを割り当てると、この2つが競合する。
書誌名の上での長押しはテキスト選択側が取る可能性が高く、「長押ししても選択モードに入らない行がある」
という分かりにくい挙動になる。

**案A（推奨）**: 対象5画面の一覧の行を `DisableSelection` で包む。一覧ではテキストのコピーが
できなくなるが、長押しは常に選択モードに入る。書誌名のコピーは**書誌詳細のポップアップで従来どおり可能**
（ポップアップは `SelectionContainer` の内側のまま、`DisableSelection` を掛けない）。
`DisableSelection` は本棚画面で既に6箇所使っており、前例がある（`BookshelfScreen.kt:322` 他）。

**案B**: テキスト選択を残し、長押しの受け口を書誌名以外（行の余白）に限る。
どこを長押しすれば入れるのかが利用者に分からないため、推奨しない。

**案C**: 長押しをやめ、「選択」ボタンで選択モードに入る。所有者の依頼（長押し方式）と異なる。

以下は**案Aを前提に書く**。案が変わる場合は §3.3・§4 を書き直す。

### 3.3 タップと長押しの規則

`combinedClickable`（`@ExperimentalFoundationApi`、foundation 1.7.0 で使用実績あり）を行に付ける。

| 状態 | タップ | 長押し |
|---|---|---|
| 通常 | 書誌詳細を開く（現状どおり） | 選択モードに入り、その行を選択する |
| 選択モード | その行の選択を切り替える | 何もしない |

- **選択できない行**（蔵書検索・新着で資料番号が空、貸出中で延長不可、予約中で取消不可）は、
  長押しでも選択モードに入らない。タップは現状どおり（詳細を開く、または何もしない）
- 選択モード中、選択できない行のタップは**何もしない**。詳細を開くと、モードの途中で別の画面へ
  飛ぶことになり分かりにくい
- 一斉操作の処理中（`anyBulkActionProcessing` 等）は、長押しもタップによる選択切り替えも受け付けない
  （現行のチェックボックスの `enabled` と同じ条件）

### 3.4 選択モードの上部バー

一覧の最上部（メンバー絞り込みチップの上）に出す。

- 左: 「N件を選択中」
- 右: 「選択解除」（選択を空にし、**選択モードからも抜ける**）
- 「すべて選択」は置かない（§2-2）
- 件数の規則は現行を踏襲する。**表示中の選択だけを数える**
  （`docs/design/bulk-selection-followup.md` §6.1）
- 選択0件でもバーは残る（§2-5）。文言は「0件を選択中」

新しい共通コンポーザブル `SelectionModeBar` を `ui/components/SelectionUi.kt` に追加する。

### 3.5 一斉操作バーの表示条件

現在は常時表示で、0件のときボタンが無効になっている。**選択モードの間だけ表示する**よう変える。
`BulkActionBar` 自体の作りは変えない（件数の文言・「⋯」メニューも現行どおり）。

### 3.6 案内メッセージ

通常のとき、一覧の上に「長押しで複数選択」を出す（§2-3）。選択モードの間は出さない
（代わりに上部バーが出る）。一覧が空のときは出さない。
体裁は既存の補助文言に合わせ、11sp・`ink2`・`chipBg` の小さな帯とする。

### 3.7 状態表示の移動

チェックボックスが消えると、1行目に残る状態表示が浮く。書誌名の下の行（出版者・貸出日などと
同じ行）へ移す。

| 画面 | 対象 | 移動後 |
|---|---|---|
| 貸出中 | 「延長可能」（`LoansScreen.kt:230` 付近） | 書誌名の下の行の末尾へ。体裁（11sp・Bold・`ink2`）は変えない |
| 予約中 | `statusLabel`（「受取可能」「順番待ち」等。`ReservationsScreen.kt:211` 付近） | 同上。`isReady` のときの色（`greenInk`）も維持する |
| 蔵書検索・新着 | 貸出可否の表示（`LendPill`） | 既に書誌名の下にあるため**変更しない** |

予約中の `statusLabel` は取消できない行にも出ており（「提供可能」「移送中」など）、
**選択の可否と状態表示の有無は別である**。移動後も全行に出す。

### 3.8 選択モードを抜ける条件

1. 「選択解除」を押した
2. **戻るキー**（`BackHandler`）。選択は解除する。書誌詳細のポップアップが開いているときは
   ポップアップ側の `BackHandler` が先に働く（現行どおり）
3. 一斉操作が完了したとき（成否を問わない）。現行も完了時に選択を空にしている
4. **他画面へ移ったとき**。`LibraryApp.navigateTo` から各コントローラへ通知する。
   蔵書検索・新着は既存の `resetOnLeave()` に含める。貸出中・予約中は新たに
   `exitSelectionMode()` を設け、`navigateTo` から呼ぶ
5. 一覧が空になったとき（絞り込みの変更などで表示行が0件）は**抜けない**（§2-5と同じ考え方）

選択が0件になっても抜けない（§2-5）。

### 3.9 対象外

- 予約カート画面（§2-4）。チェックボックスを常に表示したままにする
- 本棚画面の資料一覧。現在チェックボックスを持たない
- 一斉操作そのものの中身（確認ダイアログ、通信、結果表示）は変えない
- 処理中の表示（ダイアログか帯か）は第3の改修で扱う

## 4. 実装の段階

**1セッション1段階**で進める。段階ごとに、実装・テスト・コミット・プッシュ・CI確認まで終える。

- **段階1**: 共通部品（`SelectionModeBar`、長押しの受け口、`DisableSelection` の適用方針）と、
  **貸出中**への適用。状態表示「延長可能」の移動を含む
- **段階2**: **予約中**への適用。`statusLabel` の移動を含む
- **段階3**: **蔵書検索・新着資料**への適用（2画面は構造がほぼ同じなのでまとめる）

第3段階（読書記録）は本設計書の対象外で、別の設計書を立てる。

## 5. テスト計画（決定論的。`StandardTestDispatcher` + `runTest`）

コントローラ側（画面ごとに同じ観点を繰り返す）:

1. 長押しに相当する `enterSelectionMode(key)` で、選択モードに入り、その行が選択される
2. 選択できない行のキーでは選択モードに入らない
3. 選択モード中の `toggleSelection` で選択が増減する。0件になっても選択モードは続く
4. 「選択解除」（`exitSelectionMode()`）で、選択が空になり選択モードから抜ける
5. 一斉操作の完了（成功・失敗の両方）で、選択モードから抜ける
6. 処理中は `enterSelectionMode`・`toggleSelection` を受け付けない
7. 蔵書検索・新着: `resetOnLeave()` で選択モードから抜ける
8. 貸出中・予約中: `exitSelectionMode()` を `navigateTo` から呼べる（コントローラ側の単体テスト）

純関数側:

9. 上部バーの件数が、表示中の選択だけを数える（既存の規則の再確認）

**UIの見た目（状態表示の移動、案内の表示・非表示、長押しの受け口）は自動テストで固定しない。**
このプロジェクトには Compose のUIテストが無く、本件のためだけに導入すると検証系の維持費が増える。
実機確認（§6）で担保する。

## 6. 手動確認（CIのAPKで実機）

1. 貸出中で書誌を長押し → 選択モードに入り、その行にチェックが付く
2. 選択モード中にタイルをタップ → 選択が切り替わる（詳細が開かない）
3. 「選択解除」→ チェックが消え、選択モードから抜ける（一斉操作のバーも消える）
4. 戻るキー → 選択モードから抜ける
5. 選択モードを抜けた状態でタイルをタップ → 書誌詳細が開く
6. 「延長可能」「順番待ち」等が書誌名の下に出ている。チェックボックスが無いときも浮いて見えない
7. 延長できない行・取消できない行を長押し → 何も起きない
8. 一斉延長を実行 → 完了後に選択モードから抜けている
9. 選択モードのまま他画面へ移って戻る → 選択モードから抜けている
10. 一覧の文字を長押し → （案Aの場合）テキスト選択は始まらない。書誌詳細では従来どおりコピーできる
11. 予約カート画面は今までどおりチェックボックスが出ている

## 7. 未解決・既知のリスク

1. §3.2 の判断待ち。案Aでは一覧でのテキストコピーができなくなる
2. 長押しは、スクロールの開始と競合しうる。`combinedClickable` の既定の長押し時間を変えない方針とし、
   実機確認で違和感がないかを見る
3. 選択モードの導入で、利用者は「まず長押し」という一手間を負う。所有者の確定事項であり、
   一覧の見た目を優先する判断である
